# Project Flanker

Flanker is a web-app strategy game adaptation of Arty Concliffe's **_Crossfire_**. This project is designed as an effort to digitize Crossfire, focusing on core gameplay mechanics rather than being a feature-complete standalone game. There isn't yet any release or feature-complete game.

## Getting Started

### Prerequisites

- Node.js and npm (for the `webui`)
- Python 3.13+ (for the `webapi` and `core`)
- Recommended: `pip` for Python dependencies

### Development Installation

- Install Python dependencies:

  ```
  pip install -r requirements.txt
  ```

- Pytest can be set up in vscode using `.vscode/settings.json`

  ```
  "python.testing.pytestEnabled": true,
  ```

  Or alternatively, run pytest manually in terminal

  ```
  python -m pytest
  ```

- Install Node.js dependencies:

  ```
  cd ./apps/webui
  npm install
  ```

- Add environment variable file to `/apps/webui/.env`. For `VITE_WEBAPI_URL`, use the same URL that the FastApi app is using; the default is `localhost:8000`.
  ```
  # Note: "VITE_" prefix is required
  VITE_WEBAPI_URL=http://localhost:8000
  ```

## Running App

- Start the `./apps/webapi/` FastAPI server, defaults to `http://localhost:8000`.

  ```
  fastapi dev ./apps/webapi --reload
  ```

  Alternatively start via vscode Python debugger using `.vscode/launch.json`.

  ```
  "name": "Python Debugger: FastAPI",
  "type": "debugpy",
  "request": "launch",
  "module": "uvicorn",
  "args": ["webapi:app", "--reload", "--app-dir", "./apps/"],
  "jinja": true
  ```

  You can use your own port with `--port` argument if the default can't be used on your device. The rest of FastAPI arguments can be found in its official docs. The URL of `./apps/webapi/` FastAPI server must match the `VITE_WEBAPI_URL` environment variable.

- Run the `./apps/webui/` development server, defaults to `http://localhost:5173/`. Run the script `dev` for development server.
  ```
  cd ./apps/webui
  npm run dev
  ```
  Or alternatively run the script `dev-expose` to expose to local network. The app would be discoverable to every device on the same WIFI.
  ```
  npm run dev-expose
  ```

## Project Structure

### `./apps/webui/`

Svelte-based web frontend for the game.

- This is the presentation (view) layer of the game. This is strictly for user interface and game visualization logic. No gameplay level logic implemented here. This is focused on managing UI states logic.
- Svelte app Vite for development and build. Contains Svelte components, routes, and static assets.
- Uses `openapi-ts` and `openapi-fetch` to generate types from `./apps/webapi/`'s OpenApi schema.

### `./apps/webapi/`

Python FastApi app serving the game logic and running the scenes. The game rules are not intended to be implemented here, only presented as view models.

- This is the service layer coordinating the actions, AI, combat units, terrain, and scenes.
- Defines API models and manages the game state.
- Intended to be run as an API or service for the webui. This bridges the gap between presentation layer and the core's actions.

### `./flanker-backend/`

- `/src/flanker_core`
  - Core game engine logic in Python. The is the domain level gameplay logic implemented in ECS architecture. The components (data models) and systems are defined here.
  - Contains `GameState` object for ECS architecture. Here implements the entities table and various ECS operations to the game state.
  - Systems represent the gameplay logic, implemented as static methods. Some system methods represent player actions, while some other represent other non-action mechanics.
- `/src/flanker_ai`
  - Game-playing AI related logic, including state representations, search policies, game-playing agent framework, and other utils.
  - This has minimal game rules interpretation. Ideally the state would interpret and handle the game rules as best as it can. The policies would be game rule agnostic.
- `/tests/` directory for pytests. Treat this more like lightweight integration tests rather than properly isolated unit tests.

### `./scenes/`

- Scene files, containing an entity table.
- The JSON schema can be generated by `./scripts/generate_scene_schema.py`, saved at gitignored `./scripts/outputs/`.
- Scenes are handled by `./apps/webapi/` and Core's `Serializer`. Scenes can be combined.

### `./scripts/`

- General case utility scripts for visualization, perftests, or generating types.
- There isn't a single coherent objective here. This is a stash of runnable scripts for utility.
